## 1. Контекст и цель

Проект меняет формат: вместо консультаций с психологами это сервис с уроками от
специалистов в разных областях. Цель ИИ-части:

```
запись урока → [1. транскрибация] → реплики с таймкодами
                                          ↓
                          [2. генерация материалов через LLM]
                          ├─ конспект
                          ├─ вопросы и ответы (оформление «вопрос - ответ» по лекции)
                          └─ позже: тезисы, глоссарий, тест
```

**Этап 1 (сделан):** загрузка записи, фоновая транскрибация, хранение и выдача результата.
**Этап 2 (не начат):** материалы из транскрипта через LLM.

Ограничения проекта: учебный, без бюджета и ключей, компьютер без видеокарты.

## 2. Принятые решения и почему

| Решение | Почему |
|---|---|
| ИИ-модуль строится поверх существующего проекта, домен переделывается постепенно | ИИ зависит от домена только одним идентификатором («урок»), ждать полной перестройки незачем |
| Заведена минимальная сущность **«урок»** вместо привязки к `appointment` |  Первым источником выбрана загрузка файла, а для неё не нужны слоты и записи на сессию |
| Первый источник аудио - **загрузка файла**, LiveKit позже | Для тестирования в основном берутся готовые записи; Egress LiveKit требует инфраструктуры, которой пока нет |
| Движок распознавания - **faster-whisper** локально | Бесплатно, без ключей, данные остаются у нас; урок не содержит чувствительных данных, но локальный запуск проще юридически |
| Транскрибация в **отдельном воркере Celery** | Модель тяжёлая, в процессе API её держать нельзя; результат нужен «после урока», а не мгновенно |
| Единый формат реплик `{start, end, text, speaker}` | Все будущие источники и движки приводятся к нему, дальше работает один код |
| Интерфейс `Transcriber` | Движок меняется одной переменной или одним новым файлом (раздел 9) |
| LLM для конспекта и вопросов-ответов - **через бесплатный облачный тариф** на этапе разработки | Локальная LLM на 16 ГБ без GPU будет очень медленной |
| Исправление ошибок распознавания отдано LLM-стадии |Достаточно развиты чтобы понять контекст и исправить, достаточно |
| Сырой транскрипт хранится всегда, очищенный - отдельной версией | Чистка может «исправить» не так; проверить можно только по оригиналу |
| В Whisper как подсказка передаётся **только тема, указанная автором**, а не название урока | Название вроде `lecture3` лишало текст пунктуации и заглавных букв и ухудшало точность (7.9) |
| Выбор модели пользователем - из готовых вариантов («Быстро» и «Точнее»), а не по имени модели | Нельзя случайно запустить огромную модель на слабом сервере; модели за вариантами меняются настройками |
| Защита от зацикливания с запасным вариантом, результат не отбрасывается | Whisper (особенно `turbo`) иногда застревает на одной фразе без ошибки (7.8) |

## 4. Как это работает

```
Клиент: POST /lessons/ (файл + название + тема)
   │
   ▼
FastAPI (LessonService)
   1. проверяет расширение; пишет файл кусками по 1 МБ в media/lessons/{uuid}.{ext}
      (лимит размера; при ошибке частично записанный файл удаляется)
   2. создаёт Lesson и LessonTranscript(status=PENDING)
   3. КОММИТИТ транзакцию (иначе воркер может не увидеть строку)
   4. transcribe_lesson_task.delay(transcript_id)  → очередь Redis
   ▼
Celery worker (tasks.transcribe_lesson)   [на каждую задачу свой движок БД без пула, 7.9]
   1. PENDING → PROCESSING (коммит сразу)
   2. transcribe_guarded(аудио, язык, подсказка, вариант модели)
        → faster-whisper на CPU, VAD включён, пакетный режим
        → результат проверяется на ЗАЦИКЛИВАНИЕ (раздел 7.8); если модель зациклилась,
          запись распознаётся запасным вариантом «Быстро»
   3. успех: DONE + сегменты + язык (+ note, если сработала защита)
      сбой: FAILED + текст ошибки
   ▼
Клиент: GET /lessons/{id}  (статус)  →  GET /lessons/{id}/transcript  (сегменты)
```

Формат сегмента:

```json
{"start": 679.2, "end": 684.9, "text": "Государство - это сложное социальное образование", "speaker": null}
```

Поле `speaker` пока всегда `null`: определение говорящих не реализовано (см. раздел 9).

**Подсказка темы (`prompt`).** При загрузке можно передать `topic`; воркер отдаёт его Whisper как
`initial_prompt`. Если автор тему не указал, подсказки нет: **название урока в Whisper не передаётся**.
Whisper подстраивает под подсказку и стиль текста, и название вроде `lecture3` оставляло транскрипт
без заглавных букв и почти без знаков препинания (7.9). Значение `topic` из формы Swagger по умолчанию -
буквально `string`; его нужно очищать перед отправкой, иначе оно тоже попадёт в Whisper.

## 5. Настройки

Переменные окружения (все необязательные; значения по умолчанию рассчитаны на CPU без видеокарты):

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `TRANSCRIBER_BACKEND` | `faster-whisper` | Какой движок использовать (фабрика в `factory.py`) |
| `WHISPER_MODEL_FAST` | `small` | Модель за вариантом «Быстро» |
| `WHISPER_MODEL_QUALITY` | `large-v3-turbo` | Модель за вариантом «Точнее» (`medium`, `large-v3` и др.) |
| `DEFAULT_TRANSCRIPTION_MODEL` | `fast` | Вариант, если пользователь не выбрал (`fast` или `quality`). Стоит `fast`, потому что у `quality` замечено зацикливание (7.7) |
| `WHISPER_DEVICE` | `cpu` | `cpu` или `cuda` (при наличии GPU) |
| `WHISPER_COMPUTE_TYPE` | `int8` | `int8` быстрее всего на CPU; на GPU обычно `float16` |
| `WHISPER_BATCHED` | `true` | Пакетный режим: на CPU в 2–3 раза быстрее (7.6). Побочный эффект: сегменты по ~30 секунд |
| `WHISPER_BATCH_SIZE` | `8` | Размер пакета в пакетном режиме |
| `TRANSCRIBE_LANGUAGE` | `ru` | Язык распознавания (`None` - определять автоматически) |
| `LESSON_AUDIO_DIR` | `media/lessons` | Куда сохраняются записи (вне публичного `/static`) |
| `MAX_LESSON_UPLOAD_MB` | `500` | Максимальный размер загрузки |

При наличии видеокарты: `WHISPER_MODEL_QUALITY=large-v3`, `WHISPER_DEVICE=cuda`, `WHISPER_COMPUTE_TYPE=float16`.

Пользователь выбирает вариант при загрузке урока, а не на уровне сервера. Менять, какая модель стоит за
вариантом, - настройками `WHISPER_MODEL_FAST` и `WHISPER_MODEL_QUALITY` (нужен перезапуск воркера).
Модель выбирается из готовых вариантов, а не свободным именем: так нельзя случайно запустить огромную
модель на слабом сервере. Выбранный вариант сохраняется в уроке.

## 6. Запуск и тесты

### 6.1. Запуск в Docker

Нужны запущенный Docker Desktop и корневой `.env` по образцу [.env.example](../.env.example)
(обязательны `RESEND_API_KEY` и `RESEND_EMAIL`, подойдут любые значения; `STATIC_DIR=./backend/static`).

```cmd
docker compose up -d --build
docker compose ps
docker logs worker 2>&1 | findstr /C:"transcribe_lesson" /C:"ready"
```

Поднимутся `backend`, `db`, `redis`, `frontend` и новый `worker`. Миграции применяет `backend` при старте.
В логе воркера должны быть `tasks.transcribe_lesson` в списке задач и строка `celery@... ready`.
При первой транскрибации воркер скачает модель в volume `whisper_models`: `small` около 460 МБ,
`large-v3-turbo` около 1,6 ГБ.

**Миграция менялась после первых коммитов.** Если проект запускали с ранней версией
(`alembic current` покажет `b7c1d2e3f4a5`, но без колонок `topic`, `transcription_model`, `note`),
откатите и накатите заново:

```cmd
docker exec backend alembic downgrade 3aea906fe27a
docker exec backend alembic upgrade head
```

(`docker compose down -v` тоже поможет, но **удалит все данные базы**.)

**Побочный эффект запуска воркера.** Раньше воркера в compose не было, и задачи отправки писем и SMS с кодами
входа копились в Redis. Теперь воркер их разбирает: с тестовыми ключами они падают с `API key is invalid` /
`invalid credentials` и повторяются (3 повтора по 20 секунд), потом отваливаются. Это не связано с
транскрибацией, но задача урока (воркер работает в один процесс) может ждать в очереди, пока этот хвост выгорит.
Если поставить настоящие ключи, накопленные коды уйдут на старые адреса и номера. Очищать Redis командой
`FLUSHDB` не стоит: там же лежат коды подтверждения и кэш.

### 6.2. Проверка вручную через Swagger

2. Код входа печатается в лог бэкенда: `docker logs backend --tail 20`, строка `Saved: test@example.com: ...`.

5. `GET /lessons/models` - должны вернуться `fast` и `quality`.
6. `POST /lessons/`: название, файл, `model`; **поле `topic` очистить** (по умолчанию там `string`).

   настоящий ответ в блоке «Server response».
7. `GET /lessons/{id}` до статуса `DONE`, затем `GET /lessons/{id}/transcript`. При статусе `FAILED`

Примерное время на двухминутной записи: `fast` около 40 секунд, `quality` около 60 секунд после того, как

### 6.3. Типичные проблемы

| Симптом | Причина | Что делать |
|---|---|---|
| Бэкенд не стартует, ошибка про `RESEND_...` | Нет этих переменных в корневом `.env` | Добавить любые значения |
| 401 `Could not validate credentials` | В Authorize вставлен весь JSON, а не токен | Вставить только строку токена |
| Статус `FAILED`, `libctranslate2... cannot enable executable stack` | Образ воркера собран без исправления | Пересобрать воркер: `docker compose build worker` (7.9) |
| Статус остаётся `PENDING` или `FAILED` сразу, в логе `attached to a different loop` | Старая версия задачи с общим пулом БД | Обновить код и перезапустить воркер (7.9) |
| Статус `PENDING` долго | Воркер занят хвостом старых писем или качает модель | `docker logs -f worker` |
| Воркер убит, код выхода 137 | Не хватает памяти Docker Desktop | Уменьшить `WHISPER_BATCH_SIZE` или использовать `fast` |
| Нет прав на запись в `backend/media` | Права на папку | Проверить права каталога |

## 7. Замеры и выводы

### 7.1. Условия

CPU Intel i5-1135G7 (4 ядра / 8 потоков), 16 ГБ ОЗУ, без дискретной видеокарты.
faster-whisper 1.1.1, модель `small`, режим `int8`, язык `ru`, VAD включён.
Расшифровка платного сервиса speech2text.ru использовалась **как база сравнения, а не как эталон**:
в ней тоже есть ошибки. Расхождение считалось как доля слов (после приведения к нижнему регистру
и удаления пунктуации), которые отличаются от расшифровки сервиса. Это не настоящая точность.

### 7.2. Скорость

| Запись | Длина | Время | Скорость |
|---|---|---|---|
| Отрывок другой лекции | 2:03 | 60 с | 0,49x от длины |
| Участок 10:50–13:30 лекции 09.09 | 2:10 | 44–58 с | около 0,4x |
| Участок 38:05–40:06 лекции 09.09 | 2:01 | 78–79 с | около 0,65x |

Оценка для часа лекции: примерно 30–40 минут. Загрузка модели занимает около 2 секунд после первого
скачивания. Разброс времени между прогонами заметный (шум ноутбука).

### 7.3. Качество

**Лекция 09.09, расхождение `small` с speech2text.ru:**

| Участок | Без подсказки | С подсказкой темы |
|---|---|---|
| 10:50–13:30, определения (130 слов) | **29%** | 45% |
| 38:05–40:06, законодательная власть (183 слова) | **26%** | 32% |

Характерные ошибки `small`: «созданной любви» вместо «созданной людьми», «верхние палаты Цедерации»
вместо «Совет Федерации», «в крючтейниках» вместо «в трёх чтениях», «нормативного сканадистства»
вместо «законодательства». У speech2text.ru эти места верные, но и у него есть ошибки
(«Вышел трек не. Зароки», «монокротическая», «вот ум недоверие»).
Пунктуации у `small` практически нет.

**Параметры faster-whisper на отрывке другой лекции (2:03), сравнивались «на глаз»:**

| Вариант | Время | Результат |
|---|---|---|
| Исходный (`beam_size=5`) | 57 с | Много искажённых слов |
| `beam_size=1` | 66 с | **Не быстрее**; появились вставки латиницей |
| `condition_on_previous_text=False` | 48 с | Появилась «подпись» из обучающих данных («Редактор субтитров Н.Новикова…») |
| `initial_prompt` (подсказка темы) | 57 с | Термины лучше на этом отрывке |
| Все три вместе | 49 с | Хуже всех: латиница и иероглифы |

**Выводы:**
- Подсказка темы помогла на одном отрывке и **ухудшила** результат на двух участках лекции 09.09.
  Эффект не доказан, поэтому в подсказку идёт только тема, которую автор указал явно; название урока
  не подставляется (подробности и проверка на настоящем уроке в 7.9).
- `beam_size=1` и `condition_on_previous_text=False` вредят.
- Результаты Whisper между запусками немного плавают, поэтому выводы по участкам в две минуты предварительные.
- Лекция построена как диктовка: лектор повторяет каждую фразу 2–3 раза. Повторы в транскрипте
  **настоящие**, их не нужно «лечить» как сбой модели. Это даёт запас прочности: LLM может сверять
  варианты одной фразы между собой.
- Сервис иногда выдаёт «галлюцинации» на тишине (выдуманные фразы-подписи в конце записи).
  Сырой транскрипт надо хранить, а известные артефакты - отсекать на этапе очистки.

В Docker (Linux) этот набор тоже потребовал отдельного исправления: библиотека `libctranslate2` не

### 7.5. Замеры моделей и настроек

Те же два участка лекции 09.09 (A: 10:50–13:30, B: 38:05–40:06), без подсказки темы, режим `int8`.
«Скорость» - время распознавания к длине звука (меньше - быстрее). «Расхождение» - с расшифровкой
speech2text.ru (грубая метрика, см. оговорку ниже).

| Конфигурация | A: время / скорость | A: расхожд. | B: время / скорость | B: расхожд. |
|---|---|---|---|---|
| `small`, потоки по умолчанию | 38 с / 0,30x | 34% | 51 с / 0,42x | 31% |
| `small`, 8 потоков | 75 с / 0,58x | 33% | 74 с / 0,61x | 28% |
| `small`, **пакетный режим** (8 потоков) | **18 с / 0,14x** | 32% | **21 с / 0,17x** | 30% |
| `large-v3-turbo`, 8 потоков | 57 с / 0,44x | 39% | 71 с / 0,59x | **75%** (сбой, см. ниже) |
| `medium`, 8 потоков | 85 с / 0,65x | 39% | 203 с / 1,68x | 29% |

Загрузка модели: `turbo` и `medium` скачивались заново (около 100 с каждая), `small` - 2–13 с.

**Оговорка про метрику.** Процент расхождения здесь плохо отражает качество. У `turbo` и `medium` на участке A
текст при чтении лучше всех («созданной людьми», «населённую гражданами», нормальные термины), но
расхождение выше (39%): они **убрали повторные диктуемые фразы**, которые есть в расшифровке сервиса.
Метрика штрафует такие пропуски. Кроме того, повторный запуск того же `small` на участке A дал 34% против 29%
в прошлый раз, то есть шум между запусками около 5 пунктов. Различия в 2–5 пунктов между конфигурациями
`small` значимыми считать нельзя. Поэтому выводы ниже опираются в первую очередь на чтение текстов.

**Выводы.**

1. **Пакетный режим `small` в 2–3 раза быстрее обычного при том же качестве** (по метрике и по чтению).
   Это даёт запас по времени, который можно потратить на более крупную модель.
2. **`cpu_threads=8` хуже, чем значение по умолчанию** (75 с против 38 с на участке A). Явно число потоков
   задавать не нужно. Возможная причина: у процессора 4 физических ядра и 8 потоков, а лишние потоки
   мешают друг другу. Это моё предположение, не проверено.
3. **`medium` даёт заметно более чистый текст**, чем `small`, но в обычном режиме нестабильна по времени:
   0,65x на участке A и 1,68x на B (медленнее реального времени). Для часа лекции это от 40 минут до двух часов.
   В тексте участка B один посторонний корейский токен («약간»).
4. **`large-v3-turbo` в обычном режиме опасна:** на участке B она зациклилась на фразе «Что это такое?»
   и потеряла остаток участка (75% расхождения). Такие «петли» - известное поведение Whisper на длинных
   записях; пакетный режим, где куски обрабатываются независимо, им должен быть меньше подвержен.
   Это гипотеза, её нужно проверить замером.
5. **Все ошибки `small` видны и здесь:** «созданной любви», «Цедерации», «в крючтениях», мусорные вставки
   латиницей («Frankfurt still», «harmony sex»). Повторный запуск того же участка давал разный мусор,
   поэтому на одной попытке судить нельзя.

### 7.6. Пакетный режим для всех моделей (потоки по умолчанию)

Тот же замер, но `BatchedInferencePipeline` (`batch_size=8`) и число потоков не задаётся явно:

| Конфигурация | A: время / скорость | A: расхожд. | B: время / скорость | B: расхожд. |
|---|---|---|---|---|
| `small`, обычный режим (для сравнения, из 7.5) | 38 с / 0,30x | 34% | 51 с / 0,42x | 31% |
| `small`, пакетный | 13 с / 0,10x | 32% | 17 с / 0,14x | 30% |
| `medium`, пакетный | 32 с / 0,25x | 40% | 45 с / 0,38x | 17% |
| **`large-v3-turbo`, пакетный** | **38 с / 0,30x** | **27%** | **42 с / 0,35x** | **24%** |

**Выводы** (по чтению текстов, метрика опять неточна: `medium` на B показал 17%, но в тексте есть
«ГУЗУМА», «по сей день» вместо «по силе», «комплекс объектов»):

1. **`large-v3-turbo` в пакетном режиме даёт лучший текст и укладывается во время прежнего `small`
   в обычном режиме** (0,30–0,35x против 0,30–0,42x). Исчезли и мусор, и зацикливание, из-за которого
   `turbo` в обычном режиме потерял участок B. Правильно написаны «созданной людьми», «Нижняя палата,
   Госдума, Верхняя палата Федерации», «нормативного законодательства», «Конституция у нас всегда на
   первом месте». Остались ошибки: «в первых чтениях» вместо «в трёх чтениях», «Какой орган
   относится в кубках парламент».
2. **`medium` в пакетном режиме хуже `turbo`**: «созданной любви», «в серии общественных отношений»,
   «ГУЗУМА», «первичтениях». Обычный режим `medium` читался лучше, но он слишком медленный и нестабильный.
3. **`small`, даже в пакетном режиме, сохраняет основные ошибки** («созданные любви», «скрывчатей»,
   «скандальтистов»), зато работает быстрее всего: 0,10–0,14x.
4. `turbo` пропускает часть диктуемых повторов и выдаёт более чистый текст, но может потерять реплику.
   Для конспекта это скорее плюс, для дословной расшифровки - нужно знать.

**Практический результат:** качество можно заметно улучшить без роста времени по сравнению с прежней
конфигурацией - перейти на `large-v3-turbo` с пакетным режимом. Если нужна максимальная скорость
и допустимо меньшее качество, подойдёт `small` в пакетном режиме.

**Ограничения вывода.** Это два участка по две минуты, результаты Whisper плавают между запусками,
оценка качества - моё чтение, а не ручной подсчёт ошибок. Память (RAM) во время работы не измерялась,
`turbo` с `batch_size=8` может расходовать её заметно больше `small`. Целиком час лекции этой конфигурацией
ещё не прогонялся. По оценке (0,30–0,35x) лекция в 78 минут займёт около 25–30 минут; это экстраполяция,
а не измерение.

Пакетный режим и выбор модели пользователем **реализованы в проекте** (7.7).

### 7.7. Проверка реализованного выбора модели на настоящем движке

|---|---|---|---|---|
| `fast` | `small` | 2,3 с | 15 с (0,12x) | Читаемо, ошибки в терминах («Родичайку», «страны» вместо «странные») |
| `quality` | `large-v3-turbo` | 4,1 с | 44 с (0,36x) | Начало заметно лучше («Различают внутригосударственное и межгосударственное устройство»), но **в конце зациклилось: слово «представительство» подряд 34 раза** |
| `fast` (повторно) | `small` | 1,6 с | 17 с | Тот же текст, что в первый раз |

**Что это значит:**
- Выбор модели и пакетный режим в коде работают, смена варианта между уроками стоит 2–4 секунды.
- **Гипотеза «пакетный режим защищает `turbo` от зацикливания» не подтвердилась.** На участках лекции 09.09
  петель не было, на этом отрывке - была. Получается, что `quality` может выдать мусор в конце записи
  без какого-либо сигнала об ошибке. Поэтому вариантом по умолчанию поставлен `fast`.
- Защита от зацикливания сделана (7.8), так что `quality` теперь можно предлагать: при зацикливании
  запись автоматически распознаётся вариантом `fast` с предупреждением.
- В пакетном режиме сегменты длинные (около 30 секунд, здесь 5 сегментов на 2 минуты), а не по фразам.
  Для субтитров и ссылок «смотреть с 12:40» это грубо.

### 7.8. Защита от зацикливания

**Проблема.** Whisper иногда застревает на одной фразе и выдаёт её десятки раз, теряя остаток записи
(наблюдалось у `large-v3-turbo`, и в обычном, и в пакетном режиме), причём без какой-либо ошибки.

**Как работает** ([loops.py](../backend/src/services/transcription/loops.py),
[guarded.py](../backend/src/services/transcription/guarded.py)):

1. После распознавания текст проверяется: ищется слово или фраза до 8 слов, повторённые **подряд 5 и более раз**
   (регистр, пунктуация и «ё» не учитываются; повтор через границу сегментов тоже находится).
2. Если выбранный вариант зациклился, запись автоматически распознаётся запасным вариантом `fast`.
3. Результат не теряется никогда:
   - запасной вариант справился: сохраняется его текст и предупреждение («Вариант "Точнее" зациклился на
     фразе … Текст получен вариантом "Быстро"»);
   - зациклились оба варианта или `fast` был выбран сразу: текст сохраняется вместе с предупреждением,
     что конец записи мог распознаться неверно;
   - запасной вариант не запустился: сохраняется первый результат с предупреждением.
4. Предупреждение лежит в поле `note` транскрипта и отдаётся в `GET /lessons/{id}/transcript`.
   Статус при этом `DONE`, а `FAILED` остаётся только для настоящих ошибок.

**Почему порог 5.** Лектор диктует, повторяя фразу 2–3 раза подряд, это нормальная речь. Порог проверен
на реальных текстах: детектор не нашёл ничего ни в 15 нормальных расшифровках моих замеров, ни в полной
лекции 09.09 (78 минут), и нашёл оба известных зацикливания («представительство» 32 раза и
«Что это такое» 5 раз). Выборка небольшая, а лекция проверялась по расшифровке speech2text.ru, а не по
выводу Whisper.

**Проверка на настоящем движке.** Отрывок, на котором `turbo` зацикливался, через код проекта с
вариантом `quality`: `turbo` снова зациклился (32 повтора), защита это обнаружила и перезапустила
запись вариантом `fast`. В итоговом тексте повторов нет, предупреждение сохранено. Время: 70 секунд
вместо 44: запасной проход стоит дополнительно около 17 секунд.

**Ограничения.** Проверяются только повторы подряд, остальные «галлюцинации» не ловятся. Слово, сказанное
5 раз подряд намеренно («да да да да да»), вызовет ложное срабатывание: тогда транскрипт всё равно
сохранится, но с лишним предупреждением и, если выбран `quality`, будет получен вариантом `fast`.

### 7.9. Проверка в Docker

Тесты идут на SQLite без Celery и PostgreSQL, а замеры качества делались вне Docker, поэтому первый прогон
через Docker Compose нашёл ошибки, которых не видели ни тесты, ни замеры. Все исправлены.

**Что работает целиком** (двухминутная запись): загрузка → файл в `backend/media/lessons/` → задача в Redis →
воркер → статусы `PENDING → PROCESSING → DONE` → сегменты в `GET /lessons/{id}/transcript`. Миграция применилась
на PostgreSQL 17. Вариант `fast` отработал за 41 секунду, `quality` за 180 секунд вместе со скачиванием
`large-v3-turbo` (около 1,6 ГБ); оба `DONE`, язык `ru`, 5 сегментов. Память воркера после задачи - 1,6 ГиБ
из 7,7 (пик во время распознавания не измерялся).

| Симптом | Причина | Исправление |
|---|---|---|
| Статус `FAILED`, `libctranslate2...: cannot enable executable stack` (воспроизводится одной строкой `import ctranslate2`) | Библиотека помечена как требующая исполняемого стека, а Docker Desktop (WSL2) это запрещает | В [Dockerfile](../backend/Dockerfile) флаг сбрасывается командой `patchelf --clear-execstack` |
| Вторая задача падает за 0,06 с: `attached to a different loop`, статус остаётся `PENDING` | Celery запускает каждую задачу в новом `asyncio.run()`, а общий пул соединений с БД привязан к loop первой задачи | В [transcribe_lesson.py](../backend/src/tasks/transcribe_lesson.py) у каждой задачи свой движок без пула; ошибка теперь пишется и в лог воркера. Проверено: три задачи подряд в одном процессе. Тот же дефект остался у `cleanup_stale_slots` |
| Текст почти без заглавных букв и знаков препинания | В Whisper как подсказка уходило название урока `lecture3`, а Whisper подстраивает стиль под подсказку | В [pipeline.py](../backend/src/services/transcription/pipeline.py) подсказка берётся только из `topic` |

**Эксперимент с подсказкой** (одна запись, вариант `quality`, воркер в Docker):

| | Знаков препинания | Предложений с заглавной | Время |
|---|---|---|---|
| подсказка `lecture3` | 8 | 3 | 73 с |
| **без подсказки** | **43** | **20** | 62 с |

Разница и в точности: с подсказкой «кислород и закрыта была так же делать как и слуха нету», без неё «Дверь
закрыта была, когда вы зашли? Да. Наверное, у вас так же сделано, как и здесь». Это один файл и один прогон на
вариант, а результат Whisper плавает между запусками. Вывод уверенный только про короткое строчное название;
про осмысленную тему он ничего не говорит (раньше такая подсказка то помогала, то вредила, см. 7.3).

## 8. Что не проверено и известные ограничения

**Не проверено:**

- Расход памяти на длинных записях (час и более): измерен только в простое после двухминутной записи (1,6 ГиБ),
  пик во время распознавания и работа на лекции целиком не проверялись.
- Защита от зацикливания в Docker ни разу не сработала (в запуске `turbo` на двухминутной записи не зациклился);
  на хосте она проверена на реальном зацикливании (7.8).
- Отправка писем и SMS с настоящими ключами (тестовые ключи дают ожидаемые ошибки).
- LiveKit как источник аудио не реализован.

**Ограничения текущей реализации:**

- Формат файла проверяется по расширению, а не по содержимому. Битый файл приведёт к статусу `FAILED`.
- Повторные попытки при сбое не автоматические: упавший или устаревший транскрипт пересчитывается вручную
  через `POST /lessons/{id}/retry`. Если воркер умер посреди работы, транскрипт остаётся в `PROCESSING`, и
  повтор для него запрещён (409): сбросить такой статус можно только вручную в базе.
- Аудиофайл не удаляется ни после обработки, ни при удалении урока. Нужна политика хранения.
- Файлы лежат на локальном диске, воркер и API делят его через bind-mount. Для нескольких серверов нужно
  общее хранилище (S3 или MinIO).
- Нет эндпоинтов списка и удаления уроков. Доступ только у автора; ученикам урок не показывается.
- `speaker` всегда `null`.
- Защита от зацикливания проверяет только **повторы подряд** (7.8); другие «галлюцинации» Whisper
  (выдуманные подписи на тишине, иероглифы в тексте) не отлавливаются.
- Задача очистки слотов `cleanup_stale_slots` страдает тем же сбоем «different loop», что и исправленная задача
  транскрибации (7.9); не исправлено.
- Сегменты в пакетном режиме длинные (~30 с).
- Большие тестовые записи и расшифровки хранятся в `backend/media/` (папка в `.gitignore`), а не в
  `backend/tests/`: туда их класть нельзя, иначе они попадут в коммит.

## 9. Как расширять

### 9.1. Заменить модель или движок

- **Другая модель Whisper за вариантом:** изменить `WHISPER_MODEL_FAST` или `WHISPER_MODEL_QUALITY`
  и перезапустить воркер. Модель скачается сама. **Новый вариант для пользователя** (например,
  «Максимум» на `medium`): добавить значение в `TranscriptionModel`, запись в `catalog.py` и настройку
  с именем модели. В базе - миграция enum `transcriptionmodel`.
- **Новый движок** (GigaAM, облачное API вроде SaluteSpeech или SpeechKit): создать класс с методом
  `transcribe(audio_path, language, prompt) -> TranscriptionResult`, зарегистрировать его в
  `factory.py` под новым значением `TRANSCRIBER_BACKEND`. БД, API, очередь и задача не меняются.
  Для облачного API это порядка часа-двух; для локальной модели вроде GigaAM дольше (отдельная среда
  выполнения, нарезка длинных записей, вопрос про таймкоды и пунктуацию).
- **Ускорение:** GPU-сервер или облачное API; на CPU самый эффективный найденный приём - пакетный режим
  faster-whisper (`BatchedInferencePipeline`, в 2–3 раза быстрее на `small`, см. 7.6). Он уже включён
  (`WHISPER_BATCHED`). Число потоков вручную задавать не стоит (с 8 потоками было медленнее).
- **Защита от зацикливания** сделана (7.8). Расширить можно другими проверками (низкая «сжимаемость»
  текста, фразы-подписи на тишине, символы чужих алфавитов), а запасной вариант сделать настраиваемым.
- **Более мелкие сегменты** в пакетном режиме (если нужны точные ссылки на время): возможна повторная
  нарезка по паузам или переход на обычный режим для нужных случаев.

### 9.2. Стадия 2: материалы из транскрипта через LLM

Предлагаемая схема:
- Интерфейс `LLMClient` (как `Transcriber`): реализация под бесплатный облачный тариф и, при появлении
  ресурсов, локальная модель через Ollama.
- Таблица материалов `lesson_materials`: `lesson_id`, `type` (`summary`, `qa`, позже `glossary`, `quiz`),
  `status`, `content` (JSON), `error`. Новый тип материала - это новый промпт, без миграций.
- Промпты должны сообщать, что в тексте возможны ошибки распознавания, и требовать восстанавливать
  термины по контексту.
- Если очищенный текст показывают людям, делать его **отдельной версией**, сырой оставлять.
  Просить модель вернуть только текст, без пояснений (иначе в конец попадёт «Список исправлений»,
  как это видно в присланном вами примере правки).
- Длинные транскрипты: час лекции может не поместиться в контекст бесплатной модели. Тогда режем на части,
  делаем промежуточные резюме и собираем итог. Ограничения вывода у бесплатных тарифов жёстче, чем ввода,
  поэтому конспект (короткий вывод) дешевле, чем полная чистка текста.
- Идея для конспекта: продиктованные фразы (повторяющиеся 2–3 раза) фактически и есть конспект;
  их можно использовать как основной источник, отбрасывая организационные реплики и шутки.

### 9.3. Другие источники аудио

- **Запись звонка через LiveKit Egress.** Комната LiveKit названа по `appointment_id`
  ([calls_utils.py](../backend/src/utils/calls_utils.py)). Нужен webhook `egress_ended`, а создание
  урока и транскрипта вынести из `LessonService.create_lesson` в отдельный метод, чтобы им могли
  пользоваться и загрузка, и webhook. Формат сегментов остаётся тем же. Для раздельных дорожек участников
  можно распознавать каждую отдельно и склеивать по времени.
- Выбор места хранения Egress (локальный диск или S3) зависит от того, где развёрнут LiveKit.

### 9.4. Говорящие (диаризация)

Нужны, если делать материалы про реальные вопросы учеников и ответы преподавателя. Варианты: WhisperX с pyannote
(нужен токен Hugging Face) или раздельные дорожки LiveKit. Поле `speaker` уже есть в формате сегмента.
Для конспекта и оформления «вопрос - ответ» по лекции роли не нужны.

### 9.5. Эксплуатация

- Фоновая очистка старых аудиофайлов по сроку (по образцу [cleanup_stale_slots.py](../backend/src/tasks/cleanup_stale_slots.py)).
  **Внимание:** воркер Celery был добавлен в compose, а планировщик `beat` для периодических задач проекта
  по-прежнему не запущен (см. [STRUCTURE.md](STRUCTURE.md)).
- Список и удаление уроков, доступ учеников к уроку. Для зависшего `PROCESSING` (воркер умер посреди
  работы) можно разрешить повтор, если статус не менялся дольше заданного времени.
- Фильтр известных «галлюцинаций» Whisper (фразы-подписи на тишине) при сохранении результата.
- Хранение аудио в S3-совместимом хранилище, если сервисов станет несколько.

## 10. Открытые решения

1. **Зависший `PROCESSING`.** Если воркер умер посреди работы, повторный запуск запрещён. Нужно решить, через
   какое время считать такую транскрибацию зависшей и разрешать повтор.
2. **Вариант по умолчанию.** Сейчас `fast`. Защита от зацикливания уже есть, а подсказка с названием урока
   убрана (7.9), поэтому можно решить, переходить ли на `quality` по умолчанию. Для этого стоит проверить
   его на нескольких других записях: зацикливание наблюдалось на одном отрывке из пяти, в Docker на нём же
   его не было.
3. **Общий пул БД в периодических задачах** (`cleanup_stale_slots` и др.): исправить так же, как в задаче
   транскрибации (7.9), до запуска планировщика `beat`.
4. **Источник LLM.** Выбрать бесплатный облачный тариф или ждать
   возможности запускать модель локально.
5. **Что считать «уроком» дальше.** Пока минимальная сущность (автор, название, тема, аудио).
   Нужно решить: курсы, расписание, доступ учеников, роли.
6. **Нужны ли материалы в реальном времени** или только после урока (сейчас - после).
